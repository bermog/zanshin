# Design-system reference: folder structure

Source: page 17, "Sistema de diseño: Estructura de carpetas", of the DAW/DIW course series on design systems (the reference course). Licence CC BY-SA 4.0.
Fetched: 2026-11-14. Page last modified 2026-10-30. Original in Spanish; prose translated, names and code kept as on the page.
Based on the Sass Guidelines 7-1 architecture (https://sass-guidelin.es/es/#arquitectura).

Note: the page's first tree lists `s04_components`, `s05_layouts`, `s06_global`, but the detailed section, the `@use` list in `styles.scss` and the Angular tree all use `s04_global`, `s05_components`, `s06_layouts`. The detailed section is followed here.

## Folder tree

```
src/
 ├─ index.html
 ├─ styles.scss
 └─ styles/
     ├─ s01_utilities/
     │   ├─ _variables.scss
     │   ├─ _functions.scss
     │   ├─ _mixins.scss
     │   └─ _index.scss
     ├─ s02_vendor/
     │   └─ _index.scss
     ├─ s03_base/
     │   ├─ _system-tokens.scss
     │   ├─ _reset.scss
     │   ├─ _typography.scss
     │   └─ _index.scss
     ├─ s04_global/
     │   ├─ _g--color.scss
     │   ├─ _g--font-size.scss
     │   ├─ _g--margin.scss
     │   ├─ _g--padding.scss
     │   └─ _index.scss
     ├─ s05_components/
     │   ├─ _c-boton.scss
     │   ├─ _c-panel.scss
     │   └─ _index.scss
     └─ s06_layouts/
         ├─ _l-flex.scss
         ├─ _l-columns.scss
         └─ _index.scss
```

## Folder roles

- `s01_utilities/`: Sass tools; generates no CSS. `_variables.scss` holds the system's Sass lists and maps (`$colores`, `$font-sizes`, `$margins`, `$paddings`, `$breakpoints`, …) that feed the tokens and the globals. `_functions.scss` and `_mixins.scss` hold functions and mixins.
- `s02_vendor/`: CSS of third-party libraries and their configuration, each library in its own subfolder. `_index.scss` is empty if there are none. With Angular Material, `material/_theme-colors.scss` and `material/theme.css` (generated by `ng generate @angular/material:theme-color`) live here; neither is forwarded from `_index.scss`. Bootstrap does not go here (it is added in `angular.json`).
- `s03_base/`: `_system-tokens.scss` is the `:root` with the system tokens (`--mlt-sys-*`), generated with loops from the variables. `_reset.scss` holds the reset. `_typography.scss` imports the fonts.
- `s04_global/`: one file per type of global modifier (`_g--color.scss`, `_g--font-size.scss`, `_g--margin.scss`, `_g--padding.scss`). Responsive variants (`@tablet`, `@desktop`, `@fulldesktop`) go in the same file as the base class, always after the base classes (placed before, the base wins), generated from the `$breakpoints` map.
- `s05_components/`: one file per block of type component (`c-`) that is not an Angular component, e.g. `_c-boton.scss`.
- `s06_layouts/`: one file per block of type layout (`l-`) that is not an Angular component, e.g. `_l-flex.scss`.

Each `_index.scss` only `@forward`s the files of its folder, for example:

```scss
@forward "./_variables.scss";
@forward "./_functions.scss";
@forward "./_mixins.scss";
```

## Rules

- Every folder is named `s` plus a two-digit number; the number fixes the order. The `s` is required because Sass uses the folder name as the namespace in `@use`, and a name that starts with a digit is not valid.
- All six folders are always created, even if one holds only an empty `_index.scss`, so every project has the same structure with or without Angular and Material.
- Files in `styles/` are partials (leading `_`) so they produce no CSS of their own.
- `src/styles.scss` loads the folders with `@use`, in the order of the final CSS. `s01_utilities` is not loaded because it generates no CSS:

  ```scss
  @use "./styles/s02_vendor";
  @use "./styles/s03_base";
  @use "./styles/s04_global";
  @use "./styles/s05_components";
  @use "./styles/s06_layouts";
  ```

- Any file that uses variables, functions or mixins adds:

  ```scss
  @use "../s01_utilities/index" as utilidades;
  ```

- `@use` rules must come before any other rule in `styles.scss`, or `ng build` fails with `@use rules must be written before any other rules`.
- All CSS follows the series' guidelines for BEM, tokens and globals.
- Without Angular: compile with `npx sass --watch src/styles.scss:src/styles.css` and link only the generated `styles.css`; never edit it by hand. With Angular, the CLI compiles `styles.scss` and there is no `styles.css`.

## Angular

The Sass part is identical. In `src/app`, reusable components and layouts live in `app/shared/ui/components/<name>/` and `app/shared/ui/layouts/<name>/`; feature-specific pages and components in `app/features/<feature>/`.

A component is made one of two ways, never both:

- CSS only: `src/styles/s05_components/_c-boton.scss` with class `c-boton`, used as `<button class="c-boton">`.
- Angular component: folder `src/app/shared/ui/components/boton` with `.ts`, `.html` and `.scss`, used as `<button boton>`. Its `.scss` is written like an `s05_components` file and reaches the utilities with `@use "../../../../../styles/s01_utilities/index" as utilidades;`.

The same choice applies to layouts (`s06_layouts/_l-flex.scss` or `app/shared/ui/layouts/flex`).
